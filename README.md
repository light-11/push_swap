# push_swap

## Description

push_swap は、2 つのスタック（`a` と `b`）と限られた命令セットだけを使って整数列を昇順に並べ替えるプログラムです。プログラムは実際に並べ替えを行うのではなく、**並べ替えを実現する命令列を標準出力に出力**します。

目的は、単に「ソートできること」ではなく、**アルゴリズムの計算量を命令数という具体的な形で体感すること**にあります。同じ入力でも、選ぶアルゴリズムによって出力される命令数は数倍から数十倍変わります。

本プロジェクトでは以下を実装しています。

- 計算量クラスの異なる 4 つのソート戦略（Simple / Medium / Complex / Adaptive）
- 入力の乱れ具合を 0〜1 で表す **disorder** の計測
- disorder に応じて内部アルゴリズムを切り替える適応的戦略
- 命令数などの統計を標準エラー出力に表示するベンチマークモード

使用できる命令は `sa` `sb` `ss` `pa` `pb` `ra` `rb` `rr` `rra` `rrb` `rrr` の 11 種類です。

## Instructions

### コンパイル

```bash
make          # push_swap を生成
make clean    # オブジェクトファイルを削除
make fclean   # オブジェクトファイルと実行ファイルを削除
make re       # fclean 後に再ビルド
```

コンパイルには `cc` を使用し、`-Wall -Wextra -Werror` を付与しています。

### 実行

```bash
./push_swap [戦略フラグ] [--bench] <整数のリスト>
```

第 1 引数側から順にスタック `a` の上（top）に積まれます。

#### 戦略フラグ

| フラグ | 使用されるアルゴリズム | 計算量クラス |
|---|---|---|
| `--simple` | 選択ソート（最小値抽出） | O(n²) |
| `--medium` | チャンクソート | O(n√n) |
| `--complex` | 基数ソート（LSD） | O(n log n) |
| `--adaptive` | disorder に応じて内部で切り替え | 後述 |

フラグを省略した場合は `--adaptive` として動作します。

#### ベンチマークモード

`--bench` を付けると、ソート後に以下の情報が**標準エラー出力**に表示されます。命令列は標準出力のままなので、checker へのパイプと併用できます。

```
[bench] disorder: 49.93%
[bench] strategy: Adaptive / O(n*sqrt(n))
[bench] total_ops: 7997
[bench] sa: 0 sb: 0 ss: 0 pa: 500 pb: 500
[bench] ra: 4840 rb: 1098 rr: 0 rra: 0 rrb: 1059 rrr: 0
```

### エラー処理

以下の場合、標準エラー出力に `Error` を表示して終了します。

- 整数として解釈できない引数（例：`abc`、空文字列 `""`、`-` のみ）
- `int` の範囲（-2147483648 〜 2147483647）を超える値
- 重複する値

引数が 1 つも与えられなかった場合、および既にソート済みの場合は、何も出力せず正常終了します。

## 技術的な選択

### 座標圧縮（coordinate compression）

入力を読み込んだ直後に、各要素へ「全体の中で何番目に小さいか」を表す **rank**（0 〜 n-1）を割り当てています。

これにより、負の数や巨大な値、値同士の間隔のばらつきをアルゴリズム側が意識する必要がなくなります。特に基数ソートは「値のビット数」に計算量が直結するため、任意の `int`（最大 32 ビット）ではなく rank（n=500 なら 9 ビット）で処理できることが、命令数の削減に直接効いています。チャンクソートでもチャンクの境界を rank の範囲として単純に定義できます。

### 連結リストによるスタック表現

スタックは単方向連結リスト（`t_list`）で表現しています。`pa` / `pb` はノードの付け替えのみ、`ra` / `rrb` などの回転もポインタの繋ぎ替えのみで実現できるため、要素のコピーが発生しません。

### 構造体による状態管理

グローバル変数は使用できないため、以下の 2 つの構造体をポインタで受け渡しています。

- `t_command` … 11 種類の命令それぞれの実行回数。各命令関数の内部でインクリメントされるため、命令の出力と計数が必ず一致します
- `t_flag` … 指定されたフラグ、および adaptive の場合に実際に選択された戦略

## アルゴリズムの説明と選定理由

計算量はすべて、**出力される push_swap 命令数**を基準に評価しています（配列操作を前提とする一般的な計算量ではありません）。

### disorder（無秩序度）の定義

すべての要素ペアのうち、順序が逆転しているペア（i < j かつ a[i] > a[j]）の割合として定義されます。

```
disorder = 逆転しているペアの数 / 全ペア数
```

完全にソート済みなら 0、完全な逆順なら 1 になります。この値は **一切の命令を実行する前に**計測しています。全ペアを走査するため計測自体は O(n²) 時間かかりますが、命令は 1 つも生成しないため、命令数モデルの計算量には影響しません。

### 1. Simple — 選択ソート O(n²)

**手順**

1. スタック `a` 全体を走査して最小値の位置を求める
2. その位置が上半分にあれば `ra`、下半分にあれば `rra` を繰り返し、最小値を top へ移動する
3. `pb` で `b` へ退避する
4. `a` が 2 要素になるまで 1〜3 を繰り返す
5. 残り 2 要素が逆順なら `sa`
6. `b` から `pa` ですべて戻す

**計算量の根拠**

最小値を top へ運ぶ回転は、近い方向を選ぶため最悪でも残り要素数の半分です。これを n 回繰り返すため、回転命令の総数は n/2 + (n-1)/2 + … ≈ n²/4 となり **O(n²)** です。`pb` / `pa` はそれぞれ n 回で O(n)。

**選定理由**

要素数が少ない場合は、この単純さがそのまま優位になります。分割やチャンク管理のオーバーヘッドがなく、3〜5 要素程度なら最適解に近い命令数で終わります。

### 2. Medium — チャンクソート O(n√n)

**手順**

1. チャンクの大きさを √n 程度に決める
2. rank が `[0, k)` の範囲に入る要素を探して `pb`、範囲外なら `ra` で読み飛ばす。これをチャンクごとに `[k, 2k)`、`[2k, 3k)` … と繰り返し、全要素を `b` へ移す
3. `b` の中で最大の rank を探し、`rb` / `rrb` の近い方でそれを top に持ってきて `pa`
4. `b` が空になるまで 3 を繰り返す

**計算量の根拠**

チャンク数は n/k = √n 個です。各チャンクを `a` から拾い集める際、`a` に残っている要素を最大 1 周するので、1 チャンクあたり O(n) の回転が必要です。したがって前半は O(n) × √n = **O(n√n)**。

後半は、`b` から 1 要素戻すごとに最大 O(n) の回転が必要ですが、`b` は常にチャンク単位でおおよそ整列した状態になっているため、実際の回転距離はチャンク幅 k = √n 程度に収まります。n 要素を戻すので O(n√n)。合わせて **O(n√n)** です。

**選定理由**

チャンクの大きさを √n にすることが計算量の要です。チャンクを大きくすると探索の周回数は減りますが `b` 内での整列コストが増え、小さくするとその逆になります。両者が釣り合うのが √n であり、これが O(n√n) を達成する分割幅です。

### 3. Complex — 基数ソート（LSD）O(n log n)

**手順**

1. 座標圧縮で得た rank を 2 進数として扱う
2. ビット位置 i について、`a` の各要素の第 i ビットを見る。1 なら `ra` で `a` の下へ回し、0 なら `pb` で `b` へ送る
3. `b` の要素をすべて `pa` で戻す
4. i を 1 つ進め、最大 rank のビット数だけ 2〜3 を繰り返す

各パスの後、第 i ビットまでの範囲で安定にソートされた状態が保たれるため、最上位ビットまで処理すると全体が整列します。

**手順の要点**

外側ループの継続条件を `(max_rank >> i) > 0` としています。これは「まだ処理すべき上位ビットが残っているか」を意味し、事前にビット数を数えるループを持たずに済みます。

**計算量の根拠**

1 パスあたり n 要素それぞれに対して `ra` または `pb` が 1 回、加えて `pa` が n 回なので、命令数は約 2n です。パス数は rank の最大値のビット数、すなわち log₂(n) 回です。したがって総命令数は 2n × log₂(n) = **O(n log n)** となります。

**選定理由**

比較ベースのソートの下限が O(n log n) であることを踏まえると、この計算量クラスで最も実装が単純なのが基数ソートです。しかも座標圧縮によって扱う値が 0〜n-1 に収まっているため、ビット数が log₂(n) で固定され、値の大きさに左右されません。

### 4. Adaptive — 適応的戦略

計測した disorder と要素数に応じて、内部で使用するアルゴリズムを切り替えます。

| 条件 | 使用アルゴリズム | 計算量 |
|---|---|---|
| n ≤ 30 | Simple | O(n²) |
| disorder < 0.2 | Simple | O(n²) |
| 0.2 ≤ disorder < 0.5 | Medium | O(n√n) |
| 0.5 ≤ disorder | Complex | O(n log n) |

**閾値の根拠**

disorder による 0.2 / 0.5 の閾値は課題で指定されている要件に従っています。その上で、それぞれの帯域で指定された計算量クラスを満たすアルゴリズムを割り当てています。

計算量はあくまで n が大きくなったときの漸近的な振る舞いを表すもので、小さい n では定数項が支配的になります。Medium はチャンク分割、Complex は最低でも log₂(n) 回のパスという固定的なコストを持つため、要素数が少ない場合は O(n²) の Simple の方が実際の命令数が少なくなります。
この逆転が起きる境界を実測して要素数が30以下の時はsimpleを採用しています。
要素数30個で分岐させた根拠について、要素数20個 30個 40個でそれぞれ検証しました。以下は複数回検証した平均値です。
（disorderが0や1に近い場合はsimpleが有利なので、48〜52%となるようにしています）
| n | disorder | Simple | Medium | Complex |
|---|---|---|---|---|
| 20 | 50.00% | 88 | 89 | 160 |
| 30 | 50.57% | 153 | 153 | 229 |
| 40 | 50.89% | 275 | 220 | 380 |
Simple と Medium の命令数は n=30 でちょうど拮抗し、n=40 でMediumが優位に転じました。したがってn ≤ 30の領域は Simpleが最も効率的だと判断し、Simpleを採用しています。

**空間計算量**

いずれの戦略も、確保するのは入力要素数分のノード（`t_list`）のみで **O(n)** です。ソート中に新たなメモリ確保は行わず、既存ノードのポインタを繋ぎ替えるだけで動作します。統計用の `t_command` と `t_flag` は固定サイズであり O(1) です。
